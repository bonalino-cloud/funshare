# Ретро: be/p1-selection (задача 10)

**Задача.** `GET …/candidates`, `POST …/selection`, проверка id и числа (1..`selectCount`), авторитетная сборка артефакта из выбранных.

**Как решали.** Исполнитель (sonnet) → карусель (opus) 9/9 → чек оркестратора → PR #72 → миграция `0008` на Neon.

**Решено:** да. Живой прогон полного пути (выбор → `ready`) не делали: нужна платная генерация, пройдёт вместе с задачей 11, когда артефакт можно открыть.

**Что поймала карусель.**
- `createHook` в Vercel Workflow сам не регистрирует хук: без `getConflict()` до `write` быстрый POST мог получить 503, а конфликт токена вешал генерацию.
- INSERT артефакта проверял статус по старому снимку → возможен публичный артефакт-сирота при параллельном `failed`. Лечится `FOR UPDATE`.
- Склонение «1 шуток» в tagline и shareText — уходило бы в публичный текст шеринга.

**Что сделать лучше.** Перед работой с SDK Workflow читать доки в `node_modules` про жизненный цикл хука — исполнитель опирался на память.

**Было → стало.** Генерация вставала на `awaiting_selection`, `candidates` → 404 → полный путь до `ready` с артефактом в БД; перенос Поджог → Кострище получает выбранные по порядку.
