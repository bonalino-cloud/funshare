# fix/analyze-cover-bytes — обложки уходят модели байтами

**Задача.** Живой прогон analyze (2026-10-04, `uixlover`) показал: Anthropic не скачивает обложки по URL с CDN Instagram — 400 «disallowed by the website's robots.txt». Первая попытка всегда падала, дальше шаг шёл без картинок: модель обложек не видела никогда.

**Как решали.** Правка вне плана: исполнитель (sonnet) → отдельный проверяльщик, карусель 9/9 (opus) → чек оркестратора → живой прогон.
- `src/server/analyze/cover-fetch.ts`: сервер качает обложки сам — allowlist `*.fbcdn.net` / `*.cdninstagram.com`, только https, без редиректов, кук и `cache`, content-type + сигнатура, ≤ 3 МБ, таймаут 5 с, параллельно; неудача → обложка пропускается, `index` остальных сохраняется.
- Скачивание один раз до цикла попыток; в промпт и AI SDK идут `Uint8Array` + `mediaType`.

**Решено:** да. Живой прогон: обложки 6 из 6, досье за 45 с (было 51 с с проваленной первой попыткой), эстетика теперь описана по картинкам.

**Что поймала карусель.** Потолок 5 МБ неверен (Anthropic меряет base64, запрос ≤ 32 МБ) → 3 МБ; таймаут до начала чтения тела не обрывал чтение; тело не закрывалось на отказах (держало соединение); причины отказов не логировались → коды `host/status/type/size/read/network`; `cache: "no-store"` для фото людей.

**Что сделать лучше.** Живой прогон с картинками надо было делать до `[x]` задачи 3 — по фикстурам ошибка не видна.

**Было → стало.** Модель досье без картинок, лишний провальный вызов на каждом analyze → обложки байтами, 0 лишних вызовов.

**Открыто (фаза 2).** `look.referenceImageUrls` всё ещё ссылки на CDN Instagram с ограниченной подписью: шаг draw (KIE) может упереться в ту же проблему. Задевает контракт — решать в `be/p2-*`.
