# Ретро: be/p1-write-step (задача 9)

**Задача.** Шаг `write`: досье + факты → крючки → банк шуток → писатель ×3 → судья → до 10/20 кандидатов, перенос из Поджога в Кострище.

**Как решали.** Задачу передала сессия «Фаза-цикл». Перед стартом: живой `jokes:ingest` (526 карточек), банк одобрен Денисом целиком, язык прожарки — русский. Исполнитель (sonnet) → карусель (opus) 9/9 → живой прогон оркестратором → пачки → вторая карусель на правку 9/9.

**Решено:** да. Живой прогон на `uixlover`: Поджог 10, Кострище 20, всё по-русски.

**Что поймала карусель.**
- Сопоставление ответа модели по сырому id крючка, а в промпте он очищенный → весь крючок выбрасывался.
- Во второй карусели: оценки судьи из чужой пачки перетирали свои; одна упавшая пачка роняла всю платную генерацию.

**Что поймал живой прогон, а тесты нет.** Судья на 30 кандидатах при 4096 токенах вывода падал LlmSchemaError — моки этого не видят. Вывод: для шагов с LLM живой прогон на верхнем тарифе — обязательная часть критерия.

**Что сделать лучше.** Сразу проектировать вызовы LLM пачками и логировать `finishReason`; брать в живой прогон самый тяжёлый тариф первым.

**Было → стало.** `runWrite` — заглушка → шаг пишет кандидатов в `punch_candidates`; банк 0 одобренных → 526.
