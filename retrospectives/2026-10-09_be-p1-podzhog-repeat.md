# Ретро: be/p1-podzhog-repeat — повтор Поджога за 99 ₽ (#99)

**Задача.** Решение Сергея 06.10: Поджог больше не «один раз на человека». Первый бесплатно, каждый следующий 99 ₽. FE-часть уже была в `dev` (#101), а сервер отдавал Поджогу цену 0 и `free_used`, поэтому повтор упирался в «Уже был».

**Как решали.** `/фаза-цикл`: исполнитель (sonnet) → карусель 9/9 (opus) → чек оркестратора.
- `TIERS[1].listAmount = 9900`. Пробный тариф задан одной точкой истины `FREE_TRIAL_TIER` / `hasFreeTrial`, признак «цена 0» убран.
- `quoteFor` и `createOrder`: проба доступна → бесплатно, код игнорируется и не списывается. Проба занята (в том числе между quote и заказом) → обычный путь Кострища: без кода `payment_required`, с кодом скидка, при 100 % старт.
- `free_used` больше не отдаём, из контракта код не удалён (контракт внутри фазы только расширяется).
- Доки: roast-engine §7.1a, §9, открытый вопрос 6 и create-flow.

**Решено:** да, по BE. Фикстуры контрактов вынесены в отдельный PR (общая зона).

**Что поймала карусель.** Лишний вызов `quote()` в `quoteFor`. Мок репозитория бросал `DuplicateOrderError` не во всех вставках, а реальный SQL бросает. Подтвердила, что повтор того же `generationId` с кодом списывает код один раз, как у Кострища. Нашла, что FE-моки строят ответы из `src/contracts/fixtures/pricing.json`, где у Поджога всё ещё 0.

**Что сделать лучше.** Задачи из issue сразу заносить строкой в план фазы, чтобы цикл видел их сам. Фикстуры контрактов проверять в той же задаче, где меняется config цен: расхождение моков и прода заметно только в режиме моков.

**Было → стало.** Поджог: 0 ₽ один раз, дальше «Уже был» и `free_used` → первый бесплатно, дальше 99 ₽ по тому же пути, что Кострище, и промокод FREE работает.
