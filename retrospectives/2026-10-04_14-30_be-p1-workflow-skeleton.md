# Ретро: `be/p1-workflow-skeleton` — скелет конвейера на Vercel Workflow

**Задача.** План п.7: Vercel Workflow с шагами-заглушками, смена статусов генерации в БД, `stepTimings`, освобождение заказа при провале, реальный запуск вместо заглушки `startWorkflow`.

**Как решали.** Оркестратор → исполнитель (sonnet, цикл 5 ходов) → проверяльщик (opus, карусель 01–09) → чек оркестратора (typecheck, lint, format, 549 тестов, build: 1 workflow, 18 шагов). Ветка от `dev` после слияния #52 (API генераций сделан в параллельной сессии).

**Решено:** да по коду; `[x]` ждёт прогона `advance` на Neon.

**Ключевые решения.**
- Пакет `workflow@5.0.1`, документация прочитана в `node_modules`, не по памяти. Логика шагов — обычные функции в `pipeline.ts`, workflow — тонкая обёртка: тестируется без движка.
- Переход статуса и `stepTimings` — одна условная SQL-команда (`advance` только из ожидаемых статусов): повтор шага, двойной запуск и гонка с GET безопасны; первый `startedAt` и `finishedAt` не сдвигаются.
- Остановка на `awaiting_selection`: хук ожидания выбора ставится вместе с роутом выбора (`be/p1-selection`), иначе мёртвый код и чужой контракт. `ready` не ставится: контракт требует `artifactSlug`.

**Что поймал цикл 5 ходов исполнителя.** Повтор `draw` сдвигал `finishedAt`; лишняя зависимость `releaseOrder` от всего репозитория заказов.

**Что поймала карусель.**
- Workflow рапортовал `awaiting_selection`, хотя POST уже закрыл строку `failed` → исход `closed`.
- `.workflow-data/` (локальные данные движка) не был в `.gitignore`.

**Что сделать лучше.**
- SQL с jsonb снова проверен только по тексту. Нужен дешёвый прогон таких запросов на Neon-ветке — предложить Денису как постоянный шаг чека для задач с SQL.

**Передано дальше.** `be/p1-selection`: `createHook` с токеном `selection:<id>`, resume только из роута владельца, не `createWebhook`; подключить `runDraw`; пересмотреть исход `closed`. Сторож зависших `writing`. `import "server-only"` в коде движка (roast-engine §348) — общий долг.

**Было → стало.** Было: генерация навсегда в `queued`. Стало: настоящий запуск конвейера, статусы и тайминги в БД, возврат кода при провале.
