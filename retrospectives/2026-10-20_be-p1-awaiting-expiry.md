# Ретро: be/p1-awaiting-expiry — брошенный выбор шуток закрывается через 3 суток

**Задача.** Генерации `awaiting_selection` без выбора висели вечно и держали бесплатную пробу и промокод. Денис выбрал вариант «б», 3 суток (20.10).

**Как решали.** Исполнитель (sonnet) → карусель (opus) 9/9 → чек оркестратора. Новое не строили: добавили четвёртую ветку в `staleCondition` существующего сторожа (`be/p1-writing-watchdog`), остальное (Cron, ленивое закрытие в GET, `releaseOrder`, «сироты») уже было.

**Решено:** да.

**Что поймала карусель.** Код чист. Устаревшее «кандидаты хранятся 24 часа» в `roast-engine.md` и `create-flow.md` — привела к 3 суткам. Подтвердила: экран выбора не поллит GET, холостые UPDATE не страшны; выбор после закрытия → 409, подвешенный workflow не будится и вычислений не тратит.

**Обрыв.** Карусель упала по таймауту API на шаге 9 без строки контракта — возобновил тем же агентом, дошла до 9/9.

**Что сделать лучше.** Сторож писался с явным «решает продукт» для этого случая — хорошо, что развилку оставили отдельной: доделка заняла одну SQL-ветку.
