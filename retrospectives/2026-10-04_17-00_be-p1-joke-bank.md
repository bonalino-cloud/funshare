# Ретро: be/p1-joke-bank — банк шуток

**Задача:** план фазы 1, п.8 — таблица `joke_cards`, `jokes:ingest`, разметка, ревью-таблица; корпус вынести из публичного репо до запуска.

**Как решали:** `/фаза-цикл`: исполнитель (sonnet, цикл 5 ходов) → карусель 01–09 отдельным проверяльщиком (opus) → чек оркестратора (typecheck, lint, format:check, test 694/694, `jokes:ingest --dry-run`).

**Решено:** частично. Код, схема, миграция, CLI и ревью-таблица готовы. Не сделано: `db:migrate`, живая разметка (526 вызовов LLM), ревью CSV, вынос корпуса из репо.

**Что поймала карусель:**
- SDK валидировал весь пакет из 20 шуток целиком — одна кривая разметка роняла пакет. Теперь SDK получает только JSON Schema, каждый элемент проверяет `labelJokes` (тест на подменённой модели).
- Excel в русской локали сохраняет CSV в cp1251 → импорт отклонил бы все 526 строк с ложным «текст изменился». Теперь `CsvFormatError` с подсказкой «сохрани как CSV UTF-8».
- Шутки, удалённые из md, оставались в банке молча — теперь `jokes:ingest` перечисляет их `source`.

**Что поймал исполнитель в цикле 5 ходов:** запись одним куском теряла бы оплаченную разметку при сбое БД (стало: порции по 60); формулы Excel в скелетах (экранирование апострофом); ручная смена темы в CSV не снимает красную линию.

**Что сделать лучше:**
- Проверка, что репозиторий публичный, должна идти в начале задачи, где есть чувствительные данные: выяснилось только на сборе контекста (`gh repo view` → PUBLIC), а корпус 18+ давно лежит в истории git.
- Номер миграции снова конфликтует с открытым PR #53 (обе 0006) — второй при слиянии перенумерует через `db:generate`.
- Карусель с требованием «все 9 шагов в финальном сообщении» вернула полный отчёт с первого раза — правило из прошлого ретро работает.

**Было → стало:** корпус шуток был только md-файлом → банк карточек в БД с разметкой, флагами красных линий, которые форсирует код и CHECK в БД, и ручным одобрением через CSV.
