# Ретро: `contracts/error-codes` — коды `invalid_request` и `tier_unavailable`

**Задача.** Решение Дениса 04.10: в `ErrorCode` два новых кода вместо 400 `internal` на кривое тело и недоступный тариф.

**Как решали.** Оркестратор → исполнитель (sonnet, цикл 5 ходов) → проверяльщик (opus, карусель 01–09) → чек оркестратора (typecheck — падает только FE `errors.ts`, lint, format, 497 тестов).

**Решено:** да по BE; слияние ждёт двух строк Сергея в `ERROR_TEXT` (без них CI красный) и его ревью контракта.

**Ключевые решения.**
- `invalid_request` — только ошибка формы запроса (не JSON, нет поля, не строка). Ввод человека неверной длины остаётся его ошибкой: `invalid_url` для ссылки, `promo_invalid` для слова.
- `tier_unavailable` — 400, не 409: тариф недоступен всем одинаково.
- 404 `internal` на чужой id не тронут (защита от перебора). Миграция `0005` только добавляет значения в enum.

**Что поймала карусель.** Исполнитель превратил пустую и длинную ссылку из `invalid_url` в `invalid_request` — человек увидел бы «кривой запрос» вместо «это не ссылка». Тот же класс в `/api/quotes` для слова. Оба поправлены и закреплены тестами.

**Что сделать лучше.** Проверяльщик сначала вернул отчёт только по шагу 09 — контракт 9/9 пришлось запросить отдельно. Напоминать в промпте, что резюме нужно по всем шагам в финальном сообщении.

**Было → стало.** Было: кривой запрос и недоступный тариф — `internal`, фронт показывал «у нас сломалось». Стало: свои коды и человеческий текст.
