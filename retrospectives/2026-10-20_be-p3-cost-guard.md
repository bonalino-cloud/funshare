# Ретро: be/p3-cost-guard — дневной потолок трат на Apify

**Задача.** План: «дневной бюджет на генерации, при превышении — пауза». Денис уточнил (20.10): $5 в сутки на тестовый период, считаем только Apify.

**Как решали.** Исполнитель (sonnet) → карусель (opus) 9/9 → чек оркестратора.
- `src/server/cost/budget.ts`: счётчик `budget:apify:YYYY-MM-DD` в Upstash, микро-USD, TTL 48 ч; `INCRBY` резерва цены одного результата перед каждым `fetchRaw`, перелёт → `DECRBY` и отказ; `settle` уточняет по числу результатов.
- Два рубежа: `hasRoom` на старте `POST /api/profile-checks` (после кэша, до строки `checking`) → 429 `rate_limited`; резерв в `scrapeProfile` → `failed/rate_limited` без ретраев.
- Redis недоступен: prod закрыто (503 / `internal`), dev без Redis — пропуск с warn.
- Env: пусто/мусор → $5 + лог, `0` — выключатель.

**Решено:** да (для Apify). LLM потолком не ограничен — осознанно.

**Что поймала карусель.** Не было теста, что `failed/rate_limited` не кэшируется на 24 ч (ник можно проверить снова после полуночи) — добавлен. Подтвердила корректность Upstash API.

**Что сделать лучше.** Перед задачей «бюджет» сразу уточнять, какие траты: в плане было «на генерации», а решение — про скрейп. Ушёл лишний круг вопросов.

**Было → стало.** Было: Apify тратился без верхней границы (только лимиты на IP/устройство). Стало: не больше $5 в сутки, дальше — пауза до полуночи UTC.

**Хвосты.** FE: текст для `rate_limited` при исчерпанном бюджете (сейчас «подожди минуту»). Флейк `pnpm test` у исполнителя (1 прогон из 3) не воспроизвёлся.
