# Файл-эстафета `/фаза-цикл` — источник истины состояния автоцикла

Любая свежая сессия читает ЭТОТ файл + `CLAUDE.md` + план фаз → знает всё → продолжает.
Состояние живёт в файле, не в контексте. Поля обновляет только оркестратор, на каждой смене стадии.

## Легенда полей

| Поле | Значения | Смысл |
|---|---|---|
| `цикл_активен` | `да` / `нет` | Главный флаг. `нет` = цикл не идёт, возобновление не срабатывает. «стоп» ставит `нет`. |
| `план_фаз` | путь | Файл фазы, где искать `[ ]`-задачи. Текущая фаза — в `plans/INDEX.md`. |
| `текущая_фаза` | имя ветки задачи, напр. `be/p1-generations-api` | Какую задачу гоним сейчас. |
| `статус_фазы` | `генерация` · `исполнитель` · `карусель` · `чек` · `ждёт_обкатку` · `ждёт_принято` · `провал` | Стадия задачи. |
| `текущий_шаг_карусели` | `0`–`9` | Последний шаг карусели с отметкой ✓/✗. `0` — карусель не начата. |
| `промт_следующей_фазы` | текст / `—` | Готовый промпт следующей задачи, собирается после `[x]`. |
| `открытые_решения` | текст / `—` | Что ждёт решения Дениса: что не сошлось + 2–3 варианта. |
| `обкатка_страницы` | `да` / `нет` | Даёт ли задача изменение, видимое на странице. |
| `обкатка_чеклист` | текст / `—` | Что проверить глазами в десктоп-окне. |
| `режим_пингов` | `подробный` / `тихий` | Подробный — стадийные пинги; тихий — только финальный отчёт. |
| `потолок_на_фазу` | токены | Потолок на КАЖДОГО субагента. |
| `правила_нерушимые` | текст | Что нельзя нарушать ни при каких условиях. |

## Как читать при возобновлении

1. `цикл_активен: нет` → ничего не продолжать. Старт — только по команде Дениса.
2. `цикл_активен: да` и `статус_фазы` ∈ `генерация` / `исполнитель` / `чек` → повторить эту
   стадию для `текущая_фаза` с начала (работа исполнителя уже лежит в файлах ветки — сначала
   `git status` и `git diff $(git merge-base origin/dev HEAD)`).
3. `статус_фазы: карусель` → свежий проверяльщик с шага `текущий_шаг_карусели + 1`
   (если там уже `9` — сразу к чеку).
4. `статус_фазы: ждёт_обкатку` → повторить Денису хендофф, ждать «визуал ок» / «баг: …».
5. `статус_фазы: ждёт_принято` → ждать «дальше»; тогда брать `промт_следующей_фазы`.
6. `статус_фазы: провал` → показать `открытые_решения`, ждать выбор.
