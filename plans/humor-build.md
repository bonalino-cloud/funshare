## Простыми словами: путь одной шутки

1. У девушки в профиле куча фото из аэропортов. Версия v1 пишет «Ты очень много путешествуешь» — 👎 «поверхностно».
2. Сергей приносит приём «замещение» → карточка → новая версия v2.
3. В песочнице обе версии пишут про тех же 10 тестовых людей. v2: «У нормальных людей есть дом. У тебя — зона вылета B». Сайт не меняется.
4. Денис и Сергей оценивают 400 шуток вперемешку, не зная, где какая версия: первой 👎, второй 🔥.
5. Подсчёт: v1 — 40 % смешных, v2 — 55 %. Ворота пройдены.
6. v2 получает каждый десятый человек на сайте. Аня получила «зону вылета B», выбрала её и отправила подруге.
7. Через неделю: из шуток v2 выбирают больше и чаще делятся → v2 всем. Было бы хуже — откат одной командой.
8. «Зона вылета B» уходит в золотую полку — образец для v3.

## Что уже есть

- У каждой шутки в `punch_candidates` пишутся `promptVersion`, крючок и механика (приватная трасса).
- Банк 526 карточек с механиками (`JOKE_MECHANISMS`), `jokes:ingest`, ревью через CSV.
- `pnpm roast:try` — ручной прогон одного профиля.
- Выбор пользователя сохраняется (`punch_candidates.selected`, задача фазы 1 №10).
- Neon умеет ветки БД — тестовая база = отдельная ветка `sandbox`, боевая не участвует.

## Задачи

- [ ] H1. `be/humor-taste-pack` — **пакет вкуса с версией**
  - Всё, по чему пишутся шутки, собирается в один пакет: промпты писателя и судьи, гайд вкуса,
    золотая полка, антипримеры, карточки методик, пороги. Реестр пакетов, у каждого имя `taste/v1`, `taste/v2`…
  - Версии не смешивать: `taste/vN` — версия пакета, `roast/vN` — версия промпта внутри него. Пакет может сменить
    гайд или полку без новой версии промпта, и наоборот.
  - Базовая линия `taste/v1` = текущие промпты на момент H1: писатель и судья `roast`, модератор `moderator`
    (с политикой тем из задачи фазы 1 14а `be/p1-topics-policy`, PR #75), пороги фильтров слоя 4.
    Обёртку `withCanary` (`src/server/prompts/canary.ts`) сохранить: это метки утечки промптов, не выкатка.
  - Шаг `write` берёт пакет по имени, а не импортом `prompts/roast/v1.ts`. Имя пакета пишется в каждую шутку.
  - Критерий: `taste/v1` выдаёт ровно те же промпты, что сейчас (тест-снимок); второй пакет подключается без правки кода шага.

- [ ] H2. `be/humor-method-cards` — **карточки методик**
  - Формат карточки (zod): суть, схема-шаблон, 2–3 примера, когда работает, когда нет.
    Новая методика = новый файл карточки в пакете, без правки кода.
  - Список механик расширяется: метафора, замещение, правило трёх, callback и т. д.
  - Писатель получает методику под крючок («этот факт — через замещение»), в одной выдаче — разные методики.
    Судья получает критерий «разнообразие приёмов».
  - Критерий: добавили карточку в пакет → писатель использует её в прогоне, в трассе шутки видна методика.

- [ ] H3. `be/humor-eval-set` — **эталон и прогон двух версий** (это задача фазы 1 №15, расширенная)
  - `pnpm eval:freeze` — 10–30 публичных профилей: снимок и досье сохраняются один раз в приватное
    хранилище, не в git (личные данные). Дальше Apify не зовём.
  - `pnpm eval:run --a taste/v1 --b taste/v2` — обе версии пишут шутки по эталону, результат в тестовую базу.
  - На выходе слепая таблица (CSV): шутки перемешаны, версия скрыта, ключ «шутка → версия» лежит отдельно.
  - Защита: скрипт отказывается работать, если подключён к боевой базе.
  - Метрики DoD фазы 1 в том же прогоне: доля генераций, дошедших до `ready`, время p90, себестоимость профиля.
  - Отчёт строится на `generation_traces` (PR #77) и колонках стоимости (PR #78), без новых таблиц.
  - Критерий: прогон 10 профилей × 2 версии одной командой, цена и время прогона в отчёте. Закрывает задачу 15 фазы 1.

- [ ] H4. `be/humor-gate` — **отметки и ворота**
  - `pnpm eval:import --in marks.csv` — ваши 🔥 / 👍 / 👎 + причины в тестовую базу.
  - `pnpm eval:report` — раскрывает версии и считает: доля 🔥 + 👍, причины 👎, дубли, цена, время.
    Вердикт ворот по порогам из конфига (предложение: +10 п. п., «обидно» и «нет логики» не выросли).
  - Данные — из `generation_traces` и колонок стоимости, без новых таблиц под отчёт.
  - Отчёт — markdown, прикладывается к PR пакета.
  - Критерий: по готовой разметке одна команда даёт вердикт «проходит / не проходит» с цифрами.

- [ ] H5. `be/humor-learn` — **из отметок в следующий пакет**
  - `pnpm taste:draft --from taste/v1` — агент разбирает отметки: 🔥 → кандидаты в золотую полку,
    👎 с причинами → антипримеры, комментарии → правила гайда. Собирает черновик `taste/v-следующий` на ветке.
  - Ничего не уходит в пакет без вашего ревью в PR.
  - Критерий: после разметки черновик следующего пакета собирается одной командой.

- [ ] H6. `be/humor-rollout` — **пробная доля и откат на бою**
  - Какая версия на бою и пробная доля — строка в боевой базе, а не в коде: меняется без деплоя.
  - В коде слово `canary` не используем: оно занято метками утечки промптов (`src/server/prompts/canary.ts`).
    Имена — `rollout` / `share`.
  - `pnpm taste:rollout --pack taste/v2 --share 10` · `--promote` · `--rollback`.
  - Версия выбирается один раз при создании генерации и записывается в неё — повтор шага не меняет версию.
  - Пакет, не прошедший ворота (нет отчёта H4), на пробную долю не включается.
  - Критерий: пробная доля 10 % → примерно каждая десятая генерация на v2; откат одной командой, новые генерации снова на v1.

- [ ] H7. `be/humor-signals` — **выгрузка сигналов и сравнение вживую**
  - `pnpm taste:signals --since 7d` — только чтение боевой базы: по версии и методике —
    сколько шуток показано, сколько выбрано, сколько шерингов. Без ников и текстов профилей.
  - Отчёт пробной доли: v1 против v2 по доле выбранных и шерингу, рекомендация «на всех / откат / ждать ещё».
  - Отдельная роль БД только на чтение.
  - Критерий: недельная выгрузка одной командой, результат ложится в материал следующего круга.

- [ ] H8. `docs/humor-cycle` — **еженедельный круг**
  - Порядок круга по шагам (кто что делает, какие команды) в [humor-track.md](humor-track.md),
    чтобы любой агент мог провести круг по команде «круг юмора».

- [ ] H9. `be/humor-lab-api` — **API «Лаборатории вкуса» для админки** — описание, критерий и макет в
  [humor-lab.md](humor-lab.md), раздел «Задача H9 и экраны».

**FE / Сергей** (после MVP, не блокирует H1–H8): раздел «Лаборатория вкуса» в админке — [humor-lab.md](humor-lab.md)
(H9, макет); события «скачал», «поделился», реакция на карточке — пишутся в `events` с id шутки.

## Бэклог дорожки

- Шаблон `title` / `tagline` / `finale` / `shareText` артефакта — сейчас вне пакета вкуса, кандидат в него.
- Длинное тире у писателя v1: ставит его вопреки промпту, слой 4 вырезает 25–40 % выхода (заметки фазы 1,
  ретро `be/p1-output-filters`). ✓ Вылечено в 14а (PR #82): писатель v2 получает данные без тире, в живом прогоне вырезано 0.

## Порядок и когда

| Когда | Задачи | Что получаем |
|---|---|---|
| После задачи фазы 1 14а и решений Дениса | H1 → H3 → H4 | Пакет `taste/v1`, эталон, слепая таблица, вердикт ворот. H3 закрывает фазу 1 (задача 15, метрики DoD) |
| Сразу после H4 | Первый круг → H2 | v1 против v2 на эталоне; карточки методик по итогам круга |
| Параллельно фазе 2 | H5, H8 | Круг повторяется без ручной сборки пакета |
| До публичного запуска (фаза 3) | H6 → H7 | Выкатка пробной долей и сравнение на живых людях |
| После H6 | H9 | Круг целиком через админку ([humor-lab.md](humor-lab.md)) |

Первые круги до запуска выкатываются просто: прошёл ворота → PR → пакет становится текущим.
Пробная доля нужна, когда появятся живые пользователи.
