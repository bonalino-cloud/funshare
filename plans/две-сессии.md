# Две сессии: продукт и юмор

Решение Дениса 2026-10-06. Работа идёт в двух окнах Claude Code одновременно, чтобы юмор не держал фазы, а фазы не держали юмор.

| | Сессия «Продукт» | Сессия «Юмор» |
|---|---|---|
| Папка | `D:\My_projects\Funshare` | `D:\My_projects\Funshare-humor` (git worktree) |
| Что делает | Фазы 1→2→3 до запуска: проверка профиля, скрейп, админка, картинки, шаринг, защита, аналитика, хвосты | Дорожка юмора: H1→H3→H4→круг→H2…, правки тем и слов, разбор шуток, оценка |
| Состояние | [фаза-цикл-state.md](фаза-цикл-state.md) | [humor-state.md](humor-state.md) |
| Планы, которые правит | `phase-1…4`, `INDEX.md` | `humor-build.md`, `humor-lab.md`, строка 15 и блок «До дорожки юмора» в `phase-1-text-mvp.md` |
| Код, которым владеет | всё в зоне BE, кроме колонки справа | `src/server/prompts/**`, `src/server/roast/**` (досье в шутки, фильтры, словари, банк шуток), `scripts/roast/**`, будущие `taste/**` и eval-скрипты |

## Правила

1. Каждая сессия работает через `/фаза-цикл` и пишет только своё состояние.
2. Ветки обеих — от свежего `origin/dev`, каждая задача — свой PR в `dev`. Перед новой задачей — `git fetch`.
3. Код из колонки другой сессии не правим. Нужна правка там — пишем строку в чужой файл состояния, в поле `входящие`, отдельным маленьким PR. Хозяин берёт её в свою очередь.
4. Общие файлы (`src/contracts/**`, `architecture/*.md`, `drizzle/**`) правит та сессия, чья задача; перед PR — `git fetch` и слияние свежего `dev`.
5. Миграции: номер берём только после `git fetch`, чтобы обе сессии не заняли один.
6. Связь двух линий одна: релиз фазы 1 (`v0.1.0`) ждёт технических метрик эталона (доля `ready`, p90, цена) из H3. Вкус шуток релизы не держит.
7. В Пульте у шага карты указано, какой сессии он принадлежит.
