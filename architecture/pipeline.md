# Конвейер генерации (зона BE)

## Шаги

| # | Шаг (`step`) | Вход | Выход | Статус для UI |
|---|---|---|---|---|
| 0 | `accept` (в API, до workflow) | `GenerationRequest` | строка `generations`, `id` | `queued` |
| 1 | `scrape` | `igUsername` | `ProfileSnapshot` | `scraping` — «Изучаем профиль» |
| 2 | `analyze` | `ProfileSnapshot` | `PersonaProfile` | `analyzing` — «Разбираемся, кто это» |
| 3 | `write` | `PersonaProfile`, `kind` | `ArtifactContent` (текст + `imagePrompts[]`) | `writing` — «Пишем досье» |
| 4 | `draw` | `imagePrompts[]` | URL картинок в Blob | `drawing` — «Рисуем иллюстрации» |
| 5 | `assemble` | всё выше | `Artifact` со `slug` | `ready` |
| — | ошибка на любом шаге после ретраев | | `errorCode` | `failed` |

Схемы всех объектов — в `src/contracts/`. Описание — в [contracts.md](contracts.md).

## Правила

1. **Каждый шаг — отдельный `"use step"`**, идемпотентный. Повтор шага не создаёт дублей в БД (upsert по `generationId`).
2. **Выход каждого шага проходит zod-схему до записи.** LLM вызываем через `generateObject` со схемой. Не прошло схему — ретрай с сообщением об ошибке в промпте (макс. 2), затем `failed`.
3. **`PersonaProfile` — источник истины.** Шаги 3–5 и все будущие типы артефактов работают только с ним, а не с сырым скрейпом. Это позволяет добавлять новые артефакты без повторного скрейпа.
4. **Кэш скрейпа 24 ч по `igUsername`**: повторная генерация по тому же профилю не платит Apify.
5. **Картинки рисуются параллельно.** Если упало меньше половины, артефакт собирается без них. Если упала половина или больше — ретрай шага.
6. **Промпты версионируются**: `src/server/prompts/<kind>/v<N>.ts`. Версия промпта пишется в запись, чтобы сравнивать качество.
7. **Гардрейлы в шаге `analyze`**: схема `PersonaProfile` содержит флаги `isPrivate`, `likelyMinor`, `insufficientData`. Любой `true` → `failed` с понятным `errorCode`, шаги 3–5 не запускаются и не тратят деньги.
8. **Тон и безопасность** — в системном промпте шага `write` (запретные темы из `business/INDEX.md`). В картинках — только стилизация, без фотореализма лица.

## Коды ошибок (`errorCode`) → текст в UI (решает FE)

| Код | Когда |
|---|---|
| `invalid_url` | ссылка не на профиль Instagram |
| `profile_not_found` | профиля нет |
| `profile_private` | профиль закрыт |
| `not_enough_data` | мало постов или пустое описание |
| `minor_detected` | похоже на профиль несовершеннолетнего |
| `rate_limited` | слишком много генераций с устройства |
| `internal` | всё остальное; подробности только в логах |

## Наблюдаемость

- В `generations` пишем время начала и конца каждого шага, модель, версию промпта, стоимость (токены + картинки + Apify).
- Стоимость (`src/server/cost/`, подробности и точность в `data.md` §«Стоимость»): `CostMeter` копит токены каждого вызова LLM (включая неудачные и ретраи, роли `analyze`/`writer`/`judge`/`moderator`) и обращения к Apify; цены в одном файле `cost/prices.ts`. Проверка профиля пишет итог в `profile_checks.cost_*` при закрытии (`ok` и `failed`), шаг генерации дописывает прогон в `generations.cost_detail` и пересчитывает `cost_cents` (ceil от суммы микро-USD) одним UPDATE, и при провале тоже. Траты проверки в стоимость генерации не входят: связь через `generations.profileCheckId`. Apify считается по оценке (число результатов × тариф), строка Apify помечена `source: "estimate"`; `estimated` у прогона ставится только при неподтверждённой цене или неизвестной модели.
- Лог стоимости: одна строка `[cost] <шаг> вход=… выход=… кэш_чтение=… кэш_запись=… вызовы_неудачные=<роль>:<всего>/<неудачных> apify_попытки_результаты=… микро_usd=… центов=…` на шаг `write` и на проверку профиля. Только числа, ни текстов, ни ников.
- В логи — полные ошибки провайдеров. В UI — только `errorCode`.
