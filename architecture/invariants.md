# Инварианты — что нельзя нарушать

Выжимка правил из других документов. Источник истины — файл в скобках; при расхождении прав он.
По этому списку карусель (шаг 01) и оркестратор `/фаза-цикл` проверяют каждое изменение.

## Продукт (`business/INDEX.md`)

1. Только публичные профили. Закрытый — вежливый отказ, дальше конвейер не идёт.
2. Похоже на несовершеннолетнего — отказ.
3. Тон — дружеский юмор. **Открыты на всех степенях** (подача жёстче от степени к степени): тело (фигура, вес, спорт, тренировки), здоровье как привычки (сон, кофе, диеты, ЗОЖ, спортзал), семья (партнёр, родители, быт, свадьба), деньги (траты, покупки, доход как он виден из профиля). **Закрыты на всех степенях**: болезни, диагнозы, инвалидность; `sensitiveEvents` (потеря близкого, болезнь, развод, переезд из-за войны); дети; национальность, религия, политика, ориентация. Внешность лица и оценочные слова про тело («толстый») и сексуальность — только на well done (18+). Правило действует в промптах и в модерации результата. Сама сфера прогноза `health` из контракта не запрещена. *Пересмотр 2026-10-05 (решение Дениса, задача 14а): правка инварианта, нужна ревью Сергея.*
4. Иллюстрации только стилизованные, без фотореалистичной копии лица.

## Данные (`architecture/data.md`)

5. Сырые данные скрейпа живут не дольше 30 дней.
6. IP и `ownerToken` хранятся только хэшем.
7. Удаление артефакта: `deletedAt`, картинки из Blob удалены, страница отдаёт 410.

## Конвейер (`architecture/pipeline.md`)

8. Каждый шаг — отдельный `"use step"`, идемпотентный: повтор не создаёт дублей (upsert по `generationId`).
9. Всё внешнее (API, LLM, скрейпер) проходит zod-схему **до** записи в БД.
10. `PersonaProfile` — источник истины: шаги после `analyze` не читают сырой скрейп.
11. Гардрейл `isPrivate` / `likelyMinor` / `insufficientData` = `true` → `failed`, платные шаги не запускаются.
12. Промпты версионируются (`src/server/prompts/<kind>/v<N>.ts`), версия пишется в запись. Опубликованный `v<N>.ts` по смыслу не правится: нужна новая версия. Canary-метки (`prompts/canary.ts`) добавляются кодом при вызове модели и версию не меняют.
13. В UI — только `errorCode` и человеческий текст; ответы провайдеров, reason модели и стеки — только в логи.

## Контракты и код (`architecture/contracts.md`, `CLAUDE.md`)

14. Внутри фазы контракт только расширяется необязательными полями; удалять и переименовывать нельзя.
15. Одно имя поля — один тип во всех ответах и событиях.
16. TypeScript strict, без `any` на границах.
17. Агент не правит файлы чужой зоны.
18. Секреты только в Vercel env; `.env*` не коммитим.
19. Никаких прямых коммитов и force-push в `main` и `dev`.
20. BE не отдаёт на фронт полей вне схемы: ответ API проходит `.parse()` перед отправкой, в `Artifact` нет сырых данных профиля.
