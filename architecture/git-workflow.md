# Git-процесс

Цель: два человека с агентами работают параллельно, не ломают друг другу код и не теряют ни дня работы.

## Постоянные ветки

| Ветка | Назначение | Кто пишет | Деплой |
|---|---|---|---|
| `main` | Продакшн. Всегда рабочий | Только merge PR из `dev` в конце фазы или релиза | Production на Vercel |
| `dev` | Интеграция. Сюда сливаются все задачи | Только merge PR из рабочих веток | Preview-деплой (стейджинг) |

Других долгоживущих веток нет. **Личных веток `fe` и `be` на всю фазу не заводим**: за неделю они расходятся с `dev`, и слияние превращается в потерю работы.

## Рабочие ветки

Создаются от свежего `dev`, живут 1–3 дня, удаляются после merge.

| Префикс | Кто | Пример |
|---|---|---|
| `fe/p<N>-<задача>` | Фронтенд | `fe/p1-landing`, `fe/p1-progress-screen` |
| `be/p<N>-<задача>` | Бэкенд | `be/p1-scrape-step`, `be/p1-generations-api` |
| `contracts/<что>` | Любой, ревью обоих | `contracts/artifact-v1`, `contracts/add-share-count` |
| `fix/<что>` | Любой, в своей зоне | `fix/og-image-cyrillic` |
| `docs/<что>` | Любой | `docs/phase-2-plan` |
| `hotfix/<что>` | Срочная починка прода: от `main`, PR в `main`, затем `main` → `dev` | `hotfix/blob-timeout` |

## Цикл одной задачи

```bash
git switch dev && git pull
git switch -c fe/p1-landing
# ... работа, коммиты ...
git push -u origin fe/p1-landing
gh pr create --draft --base dev --fill
```

1. **Draft PR — сразу после первого пуша.** Прогресс виден второму человеку, есть превью-ссылка Vercel.
2. **Пуш — в конце каждой сессии**, даже недоделанное (`wip: …`). Работа, которая лежит только на ноутбуке, считается потерянной.
3. **Раз в день** подтягивать `dev` в свою ветку: `git fetch && git merge origin/dev`.
4. Готово → «Ready for review» → CI зелёный → ревью (в своей зоне — самопроверка по чек-листу PR, в `contracts/` — второй человек) → **Squash and merge** в `dev` → ветку удалить.
5. В файле текущей фазы в `plans/` отметить задачу `[x]` в том же PR.

## Релиз фазы

1. PR `dev → main` с заголовком `release: phase N`.
2. После merge — тег: `git tag v0.N.0 && git push --tags`.
3. Прод проверяем по чек-листу «Definition of Done» фазы.

## Защита веток (настроить один раз)

Для `main` и `dev`: запрет прямого пуша и force-push, merge только через PR, обязательный зелёный CI.

> ⚠️ У приватных репозиториев на бесплатном тарифе GitHub правила защиты веток **не применяются**. Нужен GitHub Pro для владельца репо (или организация на Team), иначе правила выше держатся только на дисциплине и хуках.

## CODEOWNERS

`.github/CODEOWNERS` назначает ревьюеров по папкам зон (см. `CLAUDE.md`). Изменения в `src/contracts/` требуют апрува обоих.

## Сообщения коммитов

`<тип>(<зона>): <что сделано>`, где тип — `feat | fix | refactor | test | chore | docs | wip`, зона — `fe | be | contracts | infra`.

Пример: `feat(be): scrape step with 24h cache`.
