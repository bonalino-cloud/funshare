# Скил `/фаза-цикл` — автоцикл задач плана под присмотром

Ты — **оркестратор** в окне Claude Code проекта Funshare. За один прогон доводишь ОДНУ
задачу плана до приёмки Денисом и останавливаешься. Код пишешь не ты, а субагенты.

Режим — **под присмотром**: на завершённой задаче ВСТАЁШЬ и ждёшь от Дениса
«дальше» / «принято». Сам к следующей задаче не переходишь.

**Единица цикла** — одна `[ ]`-задача (строка вида `- [ ] \`<ветка>\` — …`) в файле
фазы `plans/phase-N-*.md`. Берёшь только задачи зоны Дениса: разделы **BE** и **Общая зона**
(общую — с пометкой в отчёте «нужно ревью Сергея»). Раздел **FE** и `Definition of Done`
не трогаешь. Текущая фаза — строка «Текущая фаза» в `plans/INDEX.md`.

---

## 0. Инвариант перед стартом

1. Прочитай `plans/фаза-цикл-state.md` (эстафета), `CLAUDE.md`, `plans/INDEX.md`,
   файл фазы из `план_фаз`.
2. Определи режим по эстафете (раздел «Как читать при возобновлении»):
   - `цикл_активен: нет` и Денис только что сказал гнать → НОВЫЙ прогон: ставь
     `цикл_активен: да`, иди к §1.
   - `цикл_активен: да` + рабочий статус (`генерация` … `чек`) → ВОЗОБНОВЛЕНИЕ: продолжи
     `текущая_фаза` с её `статус_фазы` (для карусели — с `текущий_шаг_карусели + 1`;
     если там уже `9` — сразу к чеку).
     Пинг: «↩️ Продолжаю задачу <ветка> со стадии <статус>».
   - `статус_фазы: ждёт_обкатку` → код готов, идёт визуальная обкатка; напомни хендофф
     (§4, шаг 0), жди «визуал ок» / «баг: …». `[x]` НЕ ставь.
   - `статус_фазы: ждёт_принято` → задача сделана, новую без «дальше» НЕ начинай.
   - `статус_фазы: провал` → покажи `открытые_решения`, жди выбор.
3. Соблюдай `правила_нерушимые` из эстафеты и `architecture/invariants.md`.
   Потолок субагента — `потолок_на_фазу` (по умолчанию 300k).
4. Предусловие: `git fetch` и проверь, что в `origin/dev` уже есть `package.json`, этот скил,
   `carousel/` и эстафета. Нет — СТОП и пинг «⛔ Цикл не стартует: в dev нет <чего>».
   Иначе ветка задачи от `dev` окажется без оркестрации или без каркаса.

**Эстафету обновляй на КАЖДОЙ смене стадии** (пиши на диск сразу). Поля: `текущая_фаза`,
`статус_фазы`, `текущий_шаг_карусели`, `промт_следующей_фазы`, `открытые_решения`.

> ⚠️ **ПРАВИЛО ЧИСТОГО ВЫЗОВА.** Служебную правку эстафеты делай ЧИСТЫМ вызовом Edit БЕЗ
> пояснительного текста перед ним. НИКОГДА не печатай вызов инструмента обычным текстом
> (`<invoke>`, `<parameter>` и т. п.) — это роняет ход с «malformed tool call». Пинги-строки
> давай ОТДЕЛЬНО, после успешного вызова.

## 1. Тело одной задачи

### Шаг 1 — генерация промпта (`статус_фазы: генерация`)
- Найди первую `[ ]`-задачу разделов BE / Общая зона в файле текущей фазы (сверху вниз).
  Учитывай «Точки синхронизации»: задача, которая ждёт чужого результата, пропускается
  с пометкой в отчёте. Задача, по которой уже есть ветка или открытый PR
  (`git branch -a`, `gh pr list --state open`), считается взятой и тоже пропускается
  (кроме своей `текущая_фаза` при возобновлении). Имя ветки может не совпадать с планом
  (`dan/p0-scaffold` = `be/p0-scaffold`) — сверяй по смыслу, сомнение — спроси Дениса.
  `[x]` прошлых задач живут в их ветках до слияния в `dev`. Это `текущая_фаза`.
  Часть задачи делается в кабинетах (Vercel, Neon/Marketplace, настройки GitHub) —
  субагенты её не делают: код и конфиг в репо — исполнителю, ручные шаги — чек-листом
  Денису в отчёте; `[x]` только после его «сделал».
  После «дальше» бери задачу из `промт_следующей_фазы`, если она не взята.
- Создай рабочую ветку от свежего `origin/dev` по имени из задачи и правилам `CLAUDE.md`
  (`git fetch && git switch --no-track -c <ветка> origin/dev`; ветка уже есть —
  `git switch <ветка>`).
- Собери промпт исполнителя из: текста задачи + релевантных разделов `architecture/*.md`
  (контракты, конвейер, данные) + `правила_нерушимые`. Промпт самодостаточен: пути,
  критерий приёмки, инварианты, границы зоны.
- Пинг: `▶️ Задача <ветка> запущена — промпт передан исполнителю`.

### Шаг 2 — субагент-исполнитель (`статус_фазы: исполнитель`)
- Agent tool, `subagent_type: general-purpose`, модель по умолчанию (sonnet),
  `run_in_background: false`, описание `<ветка> executor`.
- В промпт вложи: задачу + требование пройти **цикл 5 ходов из CLAUDE.md** до сдачи +
  инварианты + «правишь только папки зоны BE / src/contracts» + потолок 300k + проверки
  `pnpm install --frozen-lockfile && pnpm typecheck && pnpm lint && pnpm format:check && pnpm test`
  зелёные +
  «не коммить, не пушь» + **внешние вызовы:** никаких реальных запросов к платным и внешним
  сервисам (Apify, LLM, модели картинок, Vercel, Neon) — только моки и фикстуры; значения
  из `.env*` не выводить и не читать вслух; реальный прогон — только по отдельной команде
  Дениса + «верни КОРОТКОЕ резюме: что сделал, какие файлы, какие тесты,
  что поймал в цикле 5 ходов. Без логов и дампов».
- Пинг: `✅ Исполнение <ветка> завершено — запускаю проверку (9 шагов)`.

### Шаг 3 — субагент-проверяльщик, карусель (`статус_фазы: карусель`)
- **ДРУГОЙ** субагент (кто писал код — тот его не проверяет), `model: "opus"` ЯВНО,
  описание `<ветка> carousel`, потолок 300k, `run_in_background: false`.
- Файлы репо общие → проверяльщик видит код исполнителя (`git diff $(git merge-base origin/dev HEAD)`
  — только изменения задачи, включая незакоммиченное; голый `git diff dev` тянет чужие слияния).
  Новые файлы `git diff` не показывает — плюс `git status --short` (строки `??`).
  Правило «без внешних вызовов» из шага 2 действует и для проверяльщика.
- Механика — §2.

### Шаг 4 — чек оркестратора (`статус_фазы: чек`)
- Фиксированный чек: (а) сходится ли с текстом задачи и её критерием из плана;
  (б) не нарушены ли `правила_нерушимые` / `architecture/invariants.md`;
  (в) не тронуты ли файлы чужой зоны (`git status`); (г) что упущено.
- Проверяй САМ, не на слово: прочитай ключевые изменённые файлы, прогони
  `pnpm typecheck && pnpm lint && pnpm format:check && pnpm test`
  (`pnpm build` — если задеты маршруты, конфиг или `next.config.ts`).
- Пинг: `✅ Проверка <ветка> завершена (9/9) — прогоняю чек по плану`.

### Шаг 5 — развилка → §4.

## 2. Три слоя защиты карусели

**Слой 1 — ОДИН проверяльщик сам читает шаги по одному.** Без `SendMessage` (его нет в
бот-сессиях `--channels`, механика должна работать везде). Поручи ему прогнать
`carousel/prompts/01.md … 09.md` ровно как `/carousel`:
- читает **ровно ОДИН файл за раз** по порядку: `01.md` → выполнил → `02.md` → … → `09.md`;
- **НЕ заглядывает вперёд**: пока делает шаг N, действует так, будто шагов N+1…9 нет;
- промпты применяет ДОСЛОВНО («применяй. Diff» — реально правит код и показывает diff),
  правит только зону BE / `src/contracts`, не коммитит;
- перед каждым шагом — заголовок `=== Шаг NN: <файл> ===`;
- в конце возвращает КОРОТКОЕ резюме по каждому шагу (1–3 строки) + строку контракта
  `[шаг1:✓ шаг2:✓ … шаг9:✓]`, где у проваленного шага `шагK:✗ — причина`.

**Слой 2 — контракт завершения.** Разбери строку контракта. Нет всех 9 отметок (например,
3/9 или шаг без ✓/✗) → детерминированно **«не пройдено»**, `статус_фазы` в `чек` не двигается.
Обнови `текущий_шаг_карусели` по последнему отмеченному шагу.

**Слой 3 — переспавн + эскалация.** Вердикт неполный (застрял на шаге K, оборвался) →
свежий проверяльщик (`model: "opus"`) «продолжи карусель с шага K», итоги прошлых шагов —
кратко в промпте. До **3 раз**. Не помогло → пинг
`⚠️ Карусель <ветка> застряла на шаге K, что делаем` и стоп до решения Дениса.

Незавершённый или оборванный субагент **НИКОГДА** не считается успехом.

## 3. Пинги

Отчёты — в чат этого окна (у Funshare нет Telegram-бота). Субагент в окне не может писать
в чат по ходу, поэтому пошаговых пингов карусели нет; залипание ловит контракт 9/9.
Поток за задачу:
```
▶️ Задача <ветка> запущена — промпт передан исполнителю
✅ Исполнение <ветка> завершено — запускаю проверку (9 шагов)
✅ Проверка <ветка> завершена (9/9) — прогоняю чек по плану
[финальный отчёт §4]
```
`режим_пингов: тихий` — только финальный отчёт.

## 4. Развилки

### Если ОК (карусель 9/9 + чек сошёлся)

**Шаг 0 — гейт визуальной обкатки.** Если задача даёт изменение, видимое на странице
(`обкатка_страницы: да`; для задач зоны BE это редкость):
1. Заполни `обкатка_чеклист` — что проверить глазами и кликами.
2. Эстафета: `статус_фазы: ждёт_обкатку`.
3. Пришли хендофф:
   ```
   🖥️ Задача <ветка> — код готов и проверен (карусель 9/9, проверки зелёные).
   Следующий шаг — визуальная обкатка. Открой десктоп-окно Claude в этом проекте и вставь:
   ----------------------------------------------------------------
   Ты — ВИЗУАЛЬНАЯ ОБКАТКА задачи автоцикла /фаза-цикл. НЕ правь код.
   1) Прочитай plans/фаза-цикл-state.md — поля текущая_фаза и обкатка_чеклист.
   2) Запусти дев-сервер (preview_start name=funshare-dev, порт 3000), открой нужную страницу.
   3) Пройди обкатка_чеклист: кликай, вводи, смотри.
   4) Отчитайся по каждому пункту ✓/✗ + скрин ключевого; баг — что и где.
   5) НЕ ставь [x], эстафету и план не трогай — это сделает оркестратор.
   ----------------------------------------------------------------
   Проверяем: <чеклист кратко> · Страница: http://localhost:3000/…
   После обкатки напиши сюда: «визуал ок» или «баг: …».
   ```
4. **СТОП.** «визуал ок» / «принято» → шаги 1–6 ниже. «баг: …» → ветка «Если НЕ ОК».

Не видно глазами (`обкатка_страницы: нет`) → гейт пропусти.

1. Поставь `[x]` у задачи в файле фазы и добавь под ней вложенную строку
   `  - Итог (<дата>): <что сделано · тесты · что осталось>`.
2. Коммит на рабочей ветке: `git add` **поимённо** только файлы задачи (не `git add .`,
   не `-A`), Conventional Commits со скоупом из `CLAUDE.md`. **Push — только по команде Дениса**,
   первый раз `git push -u origin <ветка>` (ветка создана с `--no-track`).
3. **Ретроспектива** `retrospectives/YYYY-MM-DD_HH-MM_<ветка>.md` — пишешь ТЫ, не
   исполнитель: задача / как решали / решено: да-нет-частично / что поймала карусель /
   что сделать лучше / было → стало.
4. Найди следующую `[ ]`-задачу → собери её промпт → положи в `промт_следующей_фазы`.
5. Финальный отчёт:
   ```
   ✅ Задача <ветка> — <название>
   Сделано: <1–2 строки>
   Карусель 9/9: <прошла / что поправила>
   Чек: критерий ✓ · инварианты ✓ · чужая зона не тронута ✓ · упущено: —
   Статус: [x] · коммит <hash> (не запушен) · ретро записана
   Дальше: <следующая ветка> — промпт готов
   → «дальше» — гнать следующую · «пушь» — запушить ветку · «стоп» — встать
   ```
6. Эстафета: `статус_фазы: ждёт_принято`. **СТОП.** Жди «дальше».

### Если НЕ ОК (карусель упала / чек не сошёлся)

1. `[x]` **НЕ** ставь. Эстафета: `статус_фазы: провал` + `открытые_решения`
   (что не сошлось + 2–3 варианта решения).
2. Сообщи Денису: что не сошлось + варианты.
3. Жди решение → примени → вернись в нужный шаг (обычно исполнитель или карусель с шага K).

## 5. Предохранители

- **Стоп-кран:** «стоп» → цикл встаёт немедленно, эстафета `цикл_активен: нет`.
- **Потолок `потолок_на_фазу`** (300k) на КАЖДОГО субагента отдельно.
- **Незавершённый субагент ≠ успех.** Обрыв, пустой или неполный ответ → переспавн по
  слою 3 → эскалация Денису.
- **Без deploy и push** без явной команды Дениса. `git add` — поимённо, только своё.
  По `CLAUDE.md` незапушенная работа считается потерянной: на каждой остановке
  (`ждёт_принято`, `провал`, «стоп») напоминай, что ветка не запушена, и предлагай «пушь».
- **Чужая зона:** исполнитель и проверяльщик не правят FE-папки. Нужно изменение там —
  пишешь в отчёт задачу для Сергея.
- **Под присмотром:** к следующей задаче сам не переходишь — ждёшь «дальше».
